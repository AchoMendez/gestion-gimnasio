# CU-03 y HU-07 — Reserva de clases grupales

## Caso de Uso CU-03: Reservar cupo en una clase grupal

| Campo | Descripción |
|---|---|
| Actor principal | Socio (usuario con membresía activa) |
| Canal | Panel web de recepción y app móvil del socio, sobre la misma API REST |
| Precondición | El socio tiene membresía activa y la clase tiene cupos disponibles (> 0) |
| Flujo básico | 1. Visualiza el horario de clases. 2. Selecciona una clase. 3. Presiona "Reservar". 4. El sistema valida el cupo. 5. Registra la reserva y actualiza el contador. |
| Flujo alterno — sin cupos | Si la clase está llena, el sistema muestra un error y no registra la reserva. |
| Flujo alterno — reserva repetida | Si el socio ya reservó esa clase, el sistema lo informa en vez de duplicarla. |
| Postcondición | La reserva queda registrada y el cupo se actualiza igual en web y en móvil. |

## Historia de Usuario HU-07

> Como socio del gimnasio, quiero reservar un cupo en una clase grupal, para asegurar mi lugar antes de que se llene.

**Criterios de aceptación:**
- El socio puede reservar un cupo en una clase con disponibilidad (web y móvil).
- El sistema muestra error si la clase no tiene cupos disponibles.
- El socio no puede duplicar su reserva en la misma clase.
- El cupo disponible es el mismo en el panel web y en la app móvil.
